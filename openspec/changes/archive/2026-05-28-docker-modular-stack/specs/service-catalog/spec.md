## ADDED Requirements

### Requirement: Catalog lists all services with metadata
`references/catalog.md` SHALL contain a table or structured list of every available service with: service name (as used in `assets/services/`), layer, Docker service/container name, required dependencies (other services), and a one-line description.

#### Scenario: All 26+ services appear in catalog
- **WHEN** `references/catalog.md` is read
- **THEN** every service present in `assets/services/` has a corresponding entry

#### Scenario: Catalog shows service dependencies
- **WHEN** the `langfuse` entry is read
- **THEN** its dependencies list includes `postgres`, `clickhouse`, `minio`, and `valkey`

### Requirement: Catalog documents the dependency graph for auto-resolution
The catalog SHALL include an explicit dependency map that Claude can use to auto-resolve transitive dependencies when a service is selected.

#### Scenario: Dependency map is machine-readable by Claude
- **WHEN** a service is selected during scaffolding
- **THEN** Claude can look up its dependencies from the catalog and recursively add them

### Requirement: Catalog notes services requiring external secrets
Services that require API keys or credentials not generated by `.env` (e.g. `OPENAI_API_KEY`, `DISCORD_BOT_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN`) SHALL be marked in the catalog with a note indicating the required external secret.

#### Scenario: archon entry notes Claude API token requirement
- **WHEN** the `archon` entry is read
- **THEN** it notes that `CLAUDE_CODE_OAUTH_TOKEN` must be provided externally

#### Scenario: hermes entry notes Discord token requirement
- **WHEN** the `hermes` entry is read
- **THEN** it notes that `DISCORD_BOT_TOKEN` and `DISCORD_USER_ID` must be provided externally

### Requirement: Catalog notes Grafana datasources are project-specific
The catalog entry for `grafana` SHALL include a note that datasource provisioning YAMLs are not included in the template and must be added manually to `docker/grafana/config/provisioning/datasources/`.

#### Scenario: Grafana entry documents datasource location
- **WHEN** the `grafana` catalog entry is read
- **THEN** it contains a note about adding datasource files to the provisioning directory

### Requirement: Catalog documents IP assignment convention by layer
The catalog SHALL document the hardcoded IP assignment ranges used when CoreDNS mode is selected, matching the convention from the source repo: `network` → `x.x.255.y`, `data` → `x.x.254.y`, `observability` → `x.x.253.y`, `communications` → `x.x.252.y`, `app_dependency` → `x.x.251.y`, `app` → `x.x.250.y`.

#### Scenario: IP convention documented for each layer
- **WHEN** `references/catalog.md` conventions section is read
- **THEN** all six layer → IP range mappings are present
